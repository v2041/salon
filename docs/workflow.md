# Процесс разработки

## Новая фича

1. Добавьте бизнес-правило в Domain. Сразу добавьте тест в `DomainTests`.
2. Добавьте Feature: DTO, валидатор, endpoint, регистрацию в модуле.
3. Запустите `dotnet build` и `dotnet test`.
4. Обновите `README.md` §4 и `TZ.md`.
5. Передайте изменения reviewer.
6. Исправьте замечания. Повторите сборку и тесты.
7. Committer выполняет staging и commit.

Детали сценария: скилл `add-feature`.

## Коммиты

Committer коммитит автоматически после каждой задачи. Отдельная просьба не нужна.

- Без `push`.
- Без `amend`.
- Без секретов. Проверьте staged files.
- Не коммитьте `appsettings.Development.json`, `.env` и реальные ключи.

## Ревью

Reviewer читает незакоммиченные изменения. Он не правит код.

Проверки: конвенции слоев, Domain-первичность, FR-S2, секреты, `TZ.md` и `README.md`.
Вердикт `NEEDS FIXES` → исправьте, пересоберите, отправьте на повторное ревью.

## Документация

- Каждая фича обновляет `README.md` §4.
- `TZ.md` — живой документ. Закрытые требования из §2 и §5 переносите в «есть/сделано».
- Новые требования добавляйте в `TZ.md` до кода.
- Не оставляйте в `TZ.md` ложные статусы.
- Не храните счетчики тестов. Запускайте тесты.
- Меняете стек, команды или конвенции — обновите нужный файл в `docs/`.

## Текст

Комментарии, документация, отчеты и сообщения коммитов — по `STE100.md`.
Цель — около 80% строгого STE100. Короткие ответы в чате могут быть обычными.

## Проверка

- Backend: `dotnet build`, `dotnet test`.
- Frontend: `npm run lint`, `npm run build`.

Команды: `commands.md`. Секреты: `security.md`.
