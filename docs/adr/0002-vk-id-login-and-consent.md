# Вход через VK ID и согласие на обработку персональных данных

Вход по телефону и коду из Telegram удалён. Клиент входит только через VK ID. Область `phone` обязательна: без телефона вход отклоняется. Принимаем только российские номера (`PhoneNumber`). Сопоставление клиента идёт по порядку: `VkId`, затем телефон, затем создание. Совпадение по `VkId` главнее телефона: сохранённый телефон не перезаписывается. Совпадение по телефону привязывает новый `VkId`: смена аккаунта VK перезаписывает старый. Пустое имя из VK заменяется на `Клиент`; клиент правит имя на шаге «Проверьте имя» (`PATCH /api/auth/me`).

Согласие — обязательный чекбокс на экране входа. Чекбокс всегда пустой, сервер требует `consent=true`. Каждый успешный вход записывает версию политики и дату в `User`; IP не сохраняем. Версия — `ConsentPolicy.CurrentVersion`; при правке текста политики её увеличивают. Текст политики — страница `/privacy`; шаблон — `frontend/salon/content/privacy.md`, свой текст мастер пишет в `content/privacy.local.md` (в git не попадает) до публикации. Отзыв согласия — только письмом на `[email]`; отдельного экрана и эндпоинта нет.

Роль Admin даёт только телефон из `Admin:Phone` (`AdminPolicy`); сид-админ понижен миграцией. Токены VK не храним: access token нужен только для чтения профиля. `state` проверяет SDK VK ID на фронтенде; бэкенд его не принимает, подмену кода закрывает PKCE (`code_verifier`). В тестах HTTP VK ID подменяется; dev-обхода входа нет.

## Considered Options

- Телефон и код (старая схема, доставка через Telegram-бота): хранение кодов, счётчики, отправка. VK ID даёт проверенный телефон без этой инфраструктуры. Отклонили.
- Telegram Login Widget: телефон не отдаёт, пришлось бы оставить привязку номера через бота. Отклонили.
- Доверять телефону, который ввёл клиент: номер нельзя проверить. Отклонили.
- Сопоставление только по телефону или перезапись телефона из VK: смена аккаунта VK не видна, а телефон — ключ сопоставления при входе. Отклонили.
- Хранение токенов VK: после входа не нужны, лишние данные — лишний риск. Отклонили.
- Проверка `state` на бэкенде: SDK проверяет `state` сам, подмену кода закрывает PKCE. Отклонили.
- Dev-обход входа: обход может попасть в прод; тесты подменяют HTTP VK ID. Отклонили.
