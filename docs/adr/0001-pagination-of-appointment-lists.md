# Пагинация списков записей: offset и параметр scope

Списки записей клиента (`GET /api/appointments/user`) и мастера (`GET /api/appointments/all`) возвращали все записи одним ответом. Добавили offset-пагинацию: параметры `page` и `pageSize`, ответ `{ items, page, pageSize, totalCount }`. Оба экрана делят записи на «Предстоящие» и «Прошедшие», поэтому список получил обязательный параметр `scope=upcoming|past`. Граница разделов — время начала, статус не влияет. Оба эндпоинта изменили форму ответа на месте: потребитель один — фронтенд.

## Considered Options

- Курсорная пагинация: устойчива к вставкам между страницами, но сложнее и требует счётчик на каждом шаге. Отклонили: до 10k записей, вставки редкие.
- Один поток «предстоящие, затем прошедшие» с одной кнопкой: прошедшие записи не видны, пока не загружены все предстоящие. Отклонили.
- Новые роуты `/paged` при сохранении старых: лишние роуты при одном потребителе. Отклонили.
